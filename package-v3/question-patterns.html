F Foundations

"budget for a new workload with a fixed monthly limit" F1

Answer type. workspace spend limit

Set the budget at the workspace that owns the workload.

  • Spend cap set on the Default Workspace
  • Usage report with no enforcement

"estimate the monthly bill from request volume" F1

Answer type. per class token arithmetic

Multiply each token class by its own rate, then by volume.

  • Input price only
  • One average price for all models

"quality target for output that carries money risk" F1

Answer type. metric, threshold, and owner chain

Write the metric, threshold, and owner before the build.

  • Build first and tune later
  • Quality adjective with no number

"a long document must be answered in one request" F2

Answer type. window fit check before the design

Confirm that the input plus max_tokens fits the window, then curate the context.

  • Bigger window as the only fix
  • Input larger than the window

"the model must change a record or fetch fresh data" F2

Answer type. client tool loop with tool_result

Run the tool in app code and return a tool_result block.

  • Model calls the API directly
  • Prompt asks the model to act

"high volume with a quality floor and low latency" F2

Answer type. smallest tier that passes the test set

Pick the least costly tier that passes the evaluation.

  • Largest model by default
  • Model ID copied from another platform

"a call fails with a server error and the request is valid" F3

Answer type. bounded retry with backoff in caller code

Retry transient errors with a limit. Fix invalid requests first.

  • Prompt asks the model to retry
  • Retry loop with no limit

"a long job that no user waits for" F3

Answer type. batch with polling

Create a batch and poll processing_status until it is ended.

  • Longer client timeout
  • Thousands of synchronous calls in a loop

"partial output appears, then the call fails" F3

Answer type. stream event handling

Handle error events inside the stream loop.

  • Check only the HTTP status
  • Restart the job without the request ID

"a CI job needs API access without a stored secret" F4

Answer type. federation with short-lived token

Federate the workload identity when the platform issues one.

  • Long-lived key in CI secrets
  • Prompt rule that says keep the key private

"a team shares one script that uses a personal key" F4

Answer type. service account key

Create a service account key for shared workloads.

  • Personal key shared by a team
  • Legacy workspace key as the default

"regulated data must not be stored at rest" F4

Answer type. ZDR through the account team

Request ZDR after you confirm that the feature is eligible.

  • Console playground for sensitive data
  • Activity logs as a substitute for ZDR

D1 Solution design and architecture

"reduce cost for a task with a fixed input format" D1.1

Answer type. code rules over a model call

Use code for fixed mapping. Call Claude only for open input.

  • Largest model for every input
  • Model call for a field that a rule reads

"success is described only with adjectives" D1.1

Answer type. measurable criteria with threshold and owner

Add a metric, a threshold, and a named owner before the build.

  • More model tiers with no eval set
  • One demo result used as proof

"a wrong output reaches a customer" D1.1

Answer type. code check on every output

Place a deterministic check between the model and the user.

  • Prompt wording as the only control
  • Human review of every output with no check

"a failure with no known stage" D1.2

Answer type. per-stage trace before a model change

Instrument each stage and find the stage that breaks before you change the model.

  • Larger model tier
  • More human reviewers on every output

"output must be right for a downstream system" D1.2

Answer type. schema plus code check

Use structured outputs and a code check on the values.

  • Prompt that asks for valid JSON only
  • Model that checks its own draft

"the conversation must continue across turns" D1.2

Answer type. application state with full history

The application holds the history and sends it with each call.

  • Assumed server-side memory between calls
  • History kept only in one browser tab

"a fixed task with steps known in advance" D1.3

Answer type. code with a model call at the judgment step

Keep the steps in code. Call the model only where judgment is needed.

  • Agent loop for every task
  • Model plan for a fixed sequence

"steps unknown until the run starts" D1.3

Answer type. agent loop with a spend cap

Use an agent loop when the plan depends on results. Add a budget.

  • Fixed code path that cannot adapt
  • Agent with no budget and no tool list

"one judgment step with a side effect" D1.3

Answer type. tool-use loop in application code

Define one tool set. Run each tool in your code.

  • Full agent for one judgment step
  • Side effect with no tool result check

"independent specialist work with one deadline" D1.4

Answer type. lead agent with scoped subagents and a merge

Split on independent seams. Keep one lead that owns the merge.

  • Three agents with no merge
  • One agent in sequence for independent tracks

"many parallel pieces and a progress need" D1.4

Answer type. workflow run with phases and a budget

Use a workflow run. Cap spend with a session budget.

  • Chat with each agent in turn
  • Run with no budget

"entangled steps that share one context that changes over time" D1.4

Answer type. single agent

Keep one agent when each step needs the previous result.

  • Subagents for each step
  • Parallel workers that each need the full history

"a long input with independent sections and a traceability need" D1.5

Answer type. fan-out with citations and a merge check

Split at section seams. Check the merged totals in code.

  • One large call
  • Chain of unrelated sections

"steps that depend on earlier output" D1.5

Answer type. chain with a check between steps

Chain only dependent steps. Check each output before the next call.

  • Parallel calls for dependent steps
  • Chain with no check

"bulk work with no answer needed at once" D1.5

Answer type. batch processing

Use the Message Batches API for bulk work that can wait.

  • Synchronous calls for a large backlog
  • Batch for an interactive user request

"a savings claim with one term" D1.6

Answer type. all terms priced with numbers

Count the baseline, the new cost, the errors avoided, and the build and run cost.

  • Savings from labor alone
  • Adjectives such as faster or better with no figure

"a model change that lowers cost" D1.6

Answer type. cost change with a quality threshold

Keep the cost change only while the eval pass rate holds.

  • Cheapest model with no eval
  • Cost cut with no quality check

"a spend overrun risk on long agent runs" D1.6

Answer type. session budget cap

Set a session budget before the run starts.

  • Cap set after the bill arrives
  • Lower model tier as the only spend control

D2 Claude models, prompting, and context engineering

"cut cost for a high-volume task with a measured quality floor" D2.1

Answer type. lowest tier that clears the measured floor

Measure the floor first. Then choose the lowest tier that clears it.

  • Top tier for all traffic
  • A custom model before tier and effort tuning

"a subset of requests misses the quality floor on the lowest tier" D2.1

Answer type. escalate the subset that misses the floor with effort or a higher tier

Escalate only the subset that misses the floor. Keep the rest on the lower tier.

  • Traffic sent to a higher tier by default
  • No quality check at all

"user text must not change a rule" D2.2

Answer type. code enforcement with guidance in the system prompt

Enforce access in code. Use the system prompt for guidance only.

  • A rule that appears only in the system prompt
  • A longer system prompt as a lock

"downstream code must parse the answer into fields" D2.2

Answer type. structured outputs with a schema

Send the schema in output_config format. Check the stop reason before you parse.

  • A prompt that asks for JSON only
  • Pattern cleanup of prose

"accuracy falls short of the bar on a classification task" D2.3

Answer type. examples before a larger change

Add a few diverse examples, then run the evals before a larger change.

  • Custom model training first
  • Reasoning added to every call

"a prefill returns a 400 error on the newest models" D2.3

Answer type. instructions, structured outputs, or a tool in place of the prefill

Move each prefill goal into the request. Do not send a prefilled final turn.

  • Retrying the same request
  • Thinking turned off as a fix

"answer quality drops and cost rises as the history grows" D2.4

Answer type. per-turn budget with compaction or a rule-based clear

Measure growth per turn. Then compact or clear the part that grows.

  • A bigger window as the fix
  • Full history on every turn

"a long agent task loses an early constraint after a summary" D2.4

Answer type. custom summarization prompt with the constraint kept

Write a summarization prompt that keeps the constraint. Test it on later turns.

  • A summary on every turn
  • The default summary without a check

"reduce cost for a long prompt that repeats on every request" D2.5

Answer type. prompt caching on the stable prefix

Cache what repeats. Move variable content after the breakpoint.

  • Smaller model that fails the quality floor
  • Custom response cache

"cache hit rate drops to zero after a prompt change" D2.5

Answer type. prefix order or breakpoint position fix

Find the block that changes and move it after the breakpoint.

  • Longer TTL
  • More breakpoints on the same variable block

"a repeated instruction block and an output that a program must parse" D2.5

Answer type. stable template with tagged slots and tagged output

Keep the template stable. Put variable content in its own tag after the stable text.

  • A rebuilt prompt with a timestamp
  • Parsing free text with a pattern match

D3 Integration

"the agent picks the wrong tool after the tool list grows" D3.1

Answer type. scope the tool set and merge similar names

Merge tools that do the same job and remove tools the task never calls.

  • Routing layer on top of the same tool set
  • Logging every call with no removal

"a wrong write fires through a tool the task rarely needs" D3.1

Answer type. remove the write tool or cap its writes

Remove the write capability, or cap it and gate it with approval.

  • Keep all tools and log every call
  • Longer audit retention

"the tool schema cost per call rises with the library" D3.1

Answer type. tool search with deferred tools

Defer tools that few requests use and keep frequent tools non-deferred.

  • Delete tools the task still needs
  • Longer system prompt listing every tool

"the audit must name the person who asked for each action" D3.2

Answer type. per-user credential checked at the server

Give each user a credential for each server, and never share one key for all users.

  • Shared service key with a name in the prompt
  • Department-level credential

"one key reaches several teams and tenants" D3.2

Answer type. workspace scope on each key

Scope each key to one workspace and give members the least role.

  • Unscoped key with a workspace header
  • One shared workspace for all tenants

"the cloud platform must control who calls the model" D3.2

Answer type. platform IAM policy on the workspace or deployment

Use the platform identity, and scope the IAM policy to the workspace or deployment.

  • Long-lived static key in code
  • OAuth consent on Claude Platform on AWS

"the answer misses the accuracy target and breaks the latency target after several additions" D3.3

Answer type. cut the stage with the weakest measured gain

Measure each stage and cut the one whose gain is smallest for its time cost.

  • Add a bigger model for more accuracy
  • Add a reasoning stage with no measured gain

"users wait too long for the first words of a reply" D3.3

Answer type. streaming with time to first token measured

Stream the output and measure time to first token as its own metric.

  • Faster model without a measured need
  • Longer timeout in the client

"a large offline job needs results and the cost must fall" D3.3

Answer type. Message Batches API for the offline set

Move work that can wait a day to Batch, and keep interactive calls on the standard path.

  • Parallel calls with standard pricing
  • Batch for an interactive chat

"a wrong action fired somewhere in a multi-step run and no one can find which step" D3.4

Answer type. trace spans with one ID and cost per hop

Emit one trace per run, with a span for each model and tool hop.

  • More prompt logs
  • Longer log retention

"finance needs spend split by team and workspace" D3.4

Answer type. usage and cost reports grouped by workspace

Call the usage and cost reports with group_by for workspace or key.

  • App-side estimates
  • Console screenshots for a monthly total

"developer tool use must be audited and the destination must stay fixed" D3.4

Answer type. managed settings with OTel and tool detail events

Pin the telemetry destination in managed settings, and enable tool details for MCP audit.

  • Repository setting for telemetry
  • Prompt text logging for every session

"answer must name the source of each claim" D3.5

Answer type. search result blocks with citations enabled

Pass retrieved text as search results and enable citations.

  • A prompt that asks for sources in plain text
  • Citations combined with a strict JSON schema

"answer cites the wrong section after a table" D3.5

Answer type. chunker fix at document structure

Fix the chunker first, then re-index. Do not swap the model.

  • Larger embedding model
  • Larger generation model

"relevant passage is in the candidates but ranks low" D3.5

Answer type. reranking stage

Add a reranker that reorders the candidate list.

  • Larger generation model
  • Smaller chunk size without a rerank step

"answer must reflect the current value of a record" D3.6

Answer type. tool call to the source system

Read live state from a tool. Do not answer from a snapshot.

  • Faster index refresh
  • Larger model that reads the snapshot

"query contains an error code and also asks in plain words" D3.6

Answer type. hybrid retrieval

Use keyword and semantic matchers together, then merge the results.

  • Semantic index only
  • Keyword index only

"relevant passage is retrieved but ranked low" D3.6

Answer type. reranking stage

Add a reranker that reorders the candidate list.

  • Larger generation model
  • Wider index refresh

"one team and one host need one internal API" D3.7

Answer type. direct API call

Skip the protocol when no second consumer exists.

  • MCP server for a single host
  • CLI wrapper with text parsing

"several hosts in several languages share one service" D3.7

Answer type. MCP server with one schema

Build one server and let each host connect as a client.

  • Hand-rolled client per host
  • Slogan that MCP is the standard

"a Messages API request needs remote tools with no client code" D3.7

Answer type. MCP connector

Define the server in mcp_servers, then reference it from one toolset.

  • Local STDIO server in the connector
  • Resources or prompts believed to work through the connector

"agent costs 100,000 schema tokens per call with 200 tools" D3.8

Answer type. deferral with search

Defer definitions, keep a few frequent tools upfront, and search for the rest.

  • Rewrite all descriptions only
  • Remove tools from the config

"wrong tool picks rise as the catalog grows" D3.8

Answer type. smaller visible choice set

Show fewer tools per turn, and load matches on demand.

  • Larger model that reads all schemas
  • Longer system prompt with every schema

"long domain guidance must reach the agent only when relevant" D3.8

Answer type. skill with progressive disclosure

Keep metadata in the prompt, and read files on demand.

  • Full guidance in the system prompt
  • Script code pasted into context

D4 Evaluation, testing, and optimization

"a proxy score rises while the business outcome stays flat" D4.1

Answer type. primary metric on the business outcome

Make the outcome the primary metric with a threshold. Keep the proxy as a diagnostic.

  • Tune the proxy harder
  • Move to a larger model tier before the measurement

"the team needs a number for a vague quality goal" D4.1

Answer type. criterion with a threshold and an owner

Turn the goal into a measurable criterion, then attach a threshold and an owner.

  • Report a qualitative impression
  • Add more logging with no threshold

"spend rises after a change that adds more tasks to the queue" D4.1

Answer type. cost per completed task

Divide spend by completed tasks and compare that value across versions.

  • Compare cost per token only
  • Cut tokens without a check of the quality threshold

"a high average score on a clean set while production fails" D4.2

Answer type. edge and adversarial cases added to the set

Add the cases that production contains. Report scores per case type.

  • Raise the clean-set average further
  • Add a larger model tier

"grader cost is too high for a daily run" D4.2

Answer type. cheapest reliable grader per case type

Use code first. Use an LLM grader only after a reliability test.

  • Grade every case by hand
  • Skip the reliability test to save time

"an LLM grader gives scores that people do not trust" D4.2

Answer type. rubric and reliability test

Write a rubric with a fixed output format. Test the grader before it scores releases.

  • Accept the grader score without a test
  • Drop the grader and keep no check

"a full rollout shows a small score move with no control" D4.3

Answer type. A/B test with a control arm

Assign units to a control and a candidate arm, and compare one primary metric.

  • Compare two time periods
  • Ship and watch the next week

"the test shows a real lift that costs more than it returns" D4.3

Answer type. business significance check

Separate statistical significance from business value. Decide with the cost of the switch.

  • Ship because the lift is significant
  • Run the test longer to find a bigger lift

"a candidate change touches tools or permissions" D4.3

Answer type. shadow run before exposure

Measure the candidate on logged or copied traffic before users see it. (Inference)

  • Expose all users at once
  • Skip the guard metrics

"an answer states a figure that no source supports" D4.4

Answer type. grounding check with quotes and citations

Ask for quotes first, then require a citation for each claim.

  • Use a larger model tier
  • Add tools without a grounding step

"quality drops after a prompt edit while the model stays the same" D4.4

Answer type. layer-by-layer diagnosis with a split test

Name the changed layer first, then test the suspects one at a time.

  • Upgrade the model tier
  • Edit several layers at once

"cache reads fall to zero after a template edit" D4.4

Answer type. earliest divergence fix

Read cache_miss_reason, fix the earliest divergence, and confirm with cache read counts.

  • Raise the cache TTL
  • Add breakpoints on the changed block

"a nightly job must score the eval set and no user waits" D4.5

Answer type. batch processing

Send unattended work to the batch interface. Keep calls that users see synchronous.

  • Stream the nightly job
  • Move the job to a faster tier with no deadline

"latency is above the target and the quality floor is close" D4.5

Answer type. measured cut under floors

Measure each stage, then cut the lever with the least quality cost first. Check the floor after each cut.

  • Cut context and caching together with no measure
  • Move all traffic to the cheapest tier

"some tasks are easy enough for a cheaper tier" D4.5

Answer type. routing with a floor per route

Route only the task types that the cheaper tier handles above the floor.

  • Route everything to the cheapest tier
  • Route by guess with no measurement

"usage totals rise while completed tasks stay flat" D4.6

Answer type. cost per completed task line with an owner

Show spend next to completed tasks, and alert on the per-task line with a named owner.

  • Alert on total spend only
  • Cut the model tier before the data check

"live quality slides while the offline eval set still scores well" D4.6

Answer type. alert with a refreshed production sample

Page the named owner, then refresh the eval set from production samples.

  • Trust the offline score
  • Roll back the model tier before diagnosis

"behavior shifts on a stable model ID with no code change" D4.6

Answer type. baseline comparison and layer check

Compare live metrics with the baseline, then check prompts, data, and the model ID.

  • Assume a model ID fixes all output
  • Change the prompt before the evidence

D5 Governance, safety, and risk management

"a model follows a prompt sentence that forbids a limited action" D5.1

Answer type. code gate on the tool call

Enforce the limit in code. Keep the prompt sentence as guidance only.

  • Longer system prompt with more warnings
  • Remove the tool and lose the function

"instructions appear inside a document that the agent reads" D5.1

Answer type. untrusted-content handling plus a tool gate

Label and screen the content. Keep the gate on every tool the content could steer.

  • Trust a document because the company stored it
  • Allow all tools for convenience

"a shell command could read credentials or reach an unknown host" D5.1

Answer type. sandbox boundary with an empty allowed domain list

Limit shell reach by default. Add hosts and paths only when a task needs them.

  • Add every host to avoid prompts
  • Assume the sandbox covers file tools

"a loop drives spend up overnight" D5.2

Answer type. spend limit and call cap

Cap spend per workspace. Cap tool calls per run in code.

  • Longer timeout
  • Higher rate limit

"an answer states a fact that no source supports" D5.2

Answer type. quote grounding with removal of unsupported claims

Require a quote for each claim. Remove each claim that has none.

  • Larger model alone
  • Longer prompt with more warnings

"a model reaches retirement while traffic continues" D5.2

Answer type. pinned ID and tested replacement

Track usage by model. Move to an active ID before the retirement date.

  • Alias that moves to a newer snapshot
  • Wait for failed requests before a move

"an action removes records and cannot be undone" D5.3

Answer type. pre-action approval with full context

Hold the action until a reviewer approves. Show the arguments and the policy.

  • Post-action sampling only
  • Approval on every low-risk action

"a high-volume reversible workflow needs oversight" D5.3

Answer type. sampled or post-action review with rollback

Review a random sample after the action. Keep a tested undo path.

  • Manual review of every action
  • No review at all

"a team needs a check that a permission rule cannot express" D5.3

Answer type. PreToolUse hook that exits with code 2

Exit with code 2, or return permissionDecision deny, in the hook when the check fails.

  • Plain text warning with exit 0
  • Longer system prompt reminder

"regulated data must not persist after the response" D5.4

Answer type. ZDR on a ZDR-enabled organization with covered features

Enable ZDR per organization. Check feature coverage before you send data.

  • Privacy notice in the app
  • Encryption alone

"inference must run in one country" D5.4

Answer type. per-request geo plus workspace allowed geos

Set the geo on each request and restrict the workspace to that geo.

  • Region of the application server
  • Global default with a policy document

"the customer must control the keys and prove access" D5.4

Answer type. CMEK on a new workspace plus Compliance API evidence

Attach the key before the first request. Read the Activity Feed with a scoped key.

  • A team believes CMEK re-encrypts old data
  • Admin API key to export chat content

"a content policy changes often and covers several languages" D5.5

Answer type. prompt-defined policy with examples and a schema verdict

Keep the policy in the prompt with examples. Constrain the verdict to a schema.

  • Custom classifier retrained for each change
  • Keyword list only

"a classifier declines the request and the flow breaks" D5.5

Answer type. stop-reason handling with fallback

Read stop_reason on every response. Handle refusal as a normal outcome.

  • Treat refusal as a server error and resend the same request
  • Remove the built-in safety classifiers from the product

"an overall score looks good but one group performs poorly" D5.5

Answer type. per-group evaluation with a floor

Check each group against its own floor before release. (Inference)

  • Average score only
  • Generated reasons that the trace does not support

"a cheaper model proposed for a quality-sensitive task" D6.2

"a decision record is wrong after a code change" D6.4

  • Edit the old record without a trace

  • Add dashboards to the live system

"cost rises after a prompt change" D7.3
